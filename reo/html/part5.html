4.2从测试反推：文件名就是事故档案

这个项目最值得学的一点：生产事故 → 先写 repro-*.mjs 定性 → 再补成 node:test 回归 → 注释里写清现场任务 id 与时间。18 条坑里挑 6 条最能说明问题的：

坑现场与修法状态
CRLF/LF 漂移宿主 core.autocrlf=true，工作区 CRLF 而 npm 打包 LF → 每个文件「每行差一字节」，工作区哈希永远无法与安装副本比对。修法：.gitattributes 锁 * text=auto eol=lf + 一个专测仓库约束的 line-endings.test.js已修
乱码事故连「守卫测试」本身都被编码污染，只能重写成英文版（commit 9d3e1ef fix: replace mojibake-corrupted guard test）。这解释了为什么 line-endings.test.js 全文是英文已修
驳回后任务卡 runningpaused 结束没清 runs → resume 返回 409「正在运行中」（现场 task-mtk40fjd）→ repro-paused-runs.test.js已修
decide 状态破坏顺序先改 running、清 humanState 再 startTask；被 409 拒后状态不回滚 → 永久卡死（repro-decide-order.test.js，修复点在 index.js:2038-2094）已修
驳回回环空转到 maxRunsfix/submit 被反复重执行到上限，人工节点永不再触发（现场 task-mttp8q71/task-mttz5ok7y）→ humanReleased 三件套 + repro-ts-review-loop.mjs已修
task 零出边静默成功「校验通过但编排器静默判成功」vs「graph.nextNode 抛错」→ 现在运行期抛错，但 静态校验仍放过半修

其余 12 条同样具体：多轮复用节点进度卡死（agent-start 必须把 done 置回 running）、中文大文本跨块截成 U+FFFD、413 先 destroy 导致客户端只看 socket hang up、task id 路径穿越（id="."）、符号链接逃逸、0.2.x 引擎被 preset isolate、sessions.open 被移除、专用 parent 没挂 preset、弹窗半透明材质盖字……每一条都有对应测试文件。

4.7Git：这个仓库是「发布快照」，不是主开发地

事实 运行证据

HEAD 停在 2026-09-27（提交信息 sync to released 2026.9.192 state），没有 tag；而 package.json 写的是 2026.10.218。工作区有 7 个已修改未提交（client.js +134 行、index.js、3 个测试、package.json、cordis.patch.yml）+ 2 个未跟踪。历史里有大量 sync: lib/xxx 逐文件同步提交。

推论：推断 主开发发生在另一个工作副本/另一台机器，这个仓库通过 sync: 提交回灌；发布靠 tgz 而不是仓库历史。接手影响：不要用 git log 判断当前功能状态；不要 git checkout 回滚（会丢掉 218 的全部改动）；以「工作区 = 已装副本 = 最新 tgz」三方哈希为准。

6.3一句话总结

这是一个工程纪律远好于文档纪律的个人项目：orchestrator.js 那 410 行沙箱脚本 + 人工审批三件套 + 附件物化的 marker 机制，是真正经过生产事故打磨的设计；而 README 停在两个月前、发布绕过了 git、UI 靠 DOM 寄生、/dev-task 在 0.2.x 上其实是坏的。它的正确读法是：把它当「一个开发者的私人工作台」，而不是「一个可被外部依赖的产品」。
